# Fuseki in this stack

- Image: built from [config/fuseki/Dockerfile](../config/fuseki/Dockerfile) (Apache Jena Fuseki 6.2.0, Java 21), started with `FusekiServerCmd`. It adopts the Dockerfile of `secoresearch/fuseki` ([SemanticComputing/fuseki-docker](https://github.com/SemanticComputing/fuseki-docker), pinned commit) on a current `eclipse-temurin:21-jre-alpine` with the OS packages upgraded and the Jena download verified by sha512. The published `secoresearch/fuseki` image was a stale build, so it is no longer used.
- The SeCo `silk-arq` extension jar of the upstream image is **not** included (it bundled outdated, unmaintained dependencies, and nothing here uses its SPARQL functions). If you need it, add the `COPY` line described in the Dockerfile; `/javalibs` stays on the classpath.
- **Jena stays on 6.2.0.** Jena 6.3.0 removed uploading a service configuration at `POST /$/datasets` (the `-Dfuseki:allowAddByConfigFile=true` option has no effect any more and the request fails with `Service configuration from an upload file not supported`). `ckanext-fuseki` (1.2.0, the latest) creates one Fuseki dataset per CKAN dataset by posting an assembler description as a raw Turtle body, so with 6.3.0 no dataset could be published. Checked with the same request against both versions: 6.2.0 answers 200, 6.3.0 answers 400.
- Updating Jena: bump `FUSEKI_VERSION` and both sha512 values in the Dockerfile (`https://downloads.apache.org/jena/binaries/*.sha512`, older releases at archive.apache.org), then `docker compose build fuseki`. Before keeping a new version, check that dataset creation still works: `curl -u admin:<password> -X POST -H 'Content-Type: text/turtle' --data-binary @service.ttl http://fuseki:3030/$/datasets` must answer 200 (a minimal `fuseki:Service` with a `ja:MemoryDataset`), and publish a CKAN dataset with an RDF resource through `fuseki_update`. A newer Jena needs a `ckanext-fuseki` release that no longer relies on the config upload. Copy the `jena_data` volume before the first start with a new Jena version.
- Query endpoint of the `ds` dataset is `/ds/sparql` (not `/ds/query`); the dataset uses `tdb:unionDefaultGraph true`, so triples written into the default graph with `INSERT DATA` are not visible to queries, only triples in named graphs are (this is how `ckanext-fuseki` writes).
- Access: everything except `/$/ping`, `/$/status` and static files requires the Fuseki `admin` login (`config/fuseki/shiro.ini.tpl`, copied to `/fuseki-base/shiro.ini` on every start by `config/fuseki/entrypoint.sh`). The public SPARQL access goes through the CKAN extension `ckanext-fuseki`.
- `compose.yaml` overrides `entrypoint:`, which makes Compose drop the image `CMD`, so `command:` is repeated there.
- `FUSEKI_JAVA_OPTS` (`.env`) must contain `-Dfuseki:allowAddByConfigFile=true`: `ckanext-fuseki` creates a dataset per CKAN dataset by posting an assembler description to `POST /$/datasets`, which Fuseki 5.5+ only accepts with this property. See the `ckanext-fuseki` README, "Fuseki 5.x and 6.x".
- Datasets created as non-persistent are in memory and empty after a restart.
